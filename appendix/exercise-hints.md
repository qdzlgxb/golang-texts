# 练习提示与验收标准

本附录不提供完整答案，只给出判断练习是否完成的线索。

## 入门章节

- 程序能通过 `go run .` 运行。
- 输入非法参数时应返回清晰错误，不应 panic。
- 文本处理工具应能处理空输入、多行输入和包含空格的文本。

## 惯用 Go 章节

- 包名短小、语义明确，不使用 `common`、`utils` 作为默认包名。
- 接口由消费者定义，避免为了“看起来抽象”提前定义大接口。
- 表驱动测试应覆盖正常路径、边界值和错误路径。
- 泛型只在能减少重复且不损害可读性时使用。

## 工程章节

- `go test ./...`、`go vet ./...` 应通过。
- `go mod tidy` 后不应产生意外 diff。
- HTTP API 应返回明确状态码和 JSON 错误结构。
- 数据库操作应通过 `context.Context` 接收取消信号。

## 并发性能章节

- `go test -race ./...` 不应报告竞态。
- goroutine 应有退出路径，不能依赖进程结束回收。
- channel 关闭应由发送方或拥有者负责。
- 压测前后应能解释延迟、吞吐、CPU、内存变化。

## 生产安全章节

- 构建产物应能通过 `go version -m` 查看模块信息。
- CI 至少包含测试、vet、race 或漏洞检查中的关键步骤。
- `govulncheck` 发现漏洞时，应判断是否在真实调用路径上。

## AI/MCP 章节

- Provider、Tool、Agent 之间通过接口协作，不能让业务代码直接依赖某个模型 SDK。
- 工具执行应有超时、权限、输入校验和审计记录。
- MCP Server 应明确声明 capabilities，不应把本地文件系统无边界暴露给客户端。
- MCP Client 应要求用户确认高风险工具调用。
