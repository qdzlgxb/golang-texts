对应官方 examples：


## 4.1 动画的本质

2D 帧动画就是根据时间选择不同的图片区域。

```go
type Animation struct {
    Frames []image.Rectangle
    Speed  int // 每几 tick 换一帧
}

func (a Animation) Frame(tick int) image.Rectangle {
    if len(a.Frames) == 0 {
        return image.Rectangle{}
    }
    idx := (tick / a.Speed) % len(a.Frames)
    return a.Frames[idx]
}
```

如果使用图集：

```go
r := anim.Frame(g.tick)
frame := atlas.SubImage(r).(*ebiten.Image)
screen.DrawImage(frame, op)
```

## 4.2 精灵结构体

入门阶段可以这样建模：

```go
type Vec2 struct {
    X, Y float64
}

type Sprite struct {
    Pos   Vec2
    Vel   Vec2
    Image *ebiten.Image
}

func (s *Sprite) Update() {
    s.Pos.X += s.Vel.X
    s.Pos.Y += s.Vel.Y
}

func (s *Sprite) Draw(screen *ebiten.Image) {
    op := &ebiten.DrawImageOptions{}
    op.GeoM.Translate(s.Pos.X, s.Pos.Y)
    screen.DrawImage(s.Image, op)
}
```

这不是 ECS，也不是复杂引擎架构，只是把数据和行为封装起来。

## 4.3 批量精灵

官方 `sprites` 示例的重要价值是演示：即使调用很多次 `DrawImage`，只要渲染状态相同，Ebitengine 内部仍可能把它们合并为较少的 GPU draw command。

实践建议：

- 尽量使用图集，而不是成千上万个独立纹理。
- 同一批精灵连续绘制。
- 不要在每个精灵之间频繁切换目标、filter、blend、shader。
- 大量对象使用切片存储，避免每帧分配。

## 4.4 场景 Scene

当游戏从一个 demo 变成完整项目，你会遇到标题画面、游戏画面、暂停画面、结算画面。可以引入 Scene 接口：

```go
type Scene interface {
    Update(g *Game) error
    Draw(screen *ebiten.Image)
}

type Game struct {
    scene Scene
}

func (g *Game) Update() error {
    return g.scene.Update(g)
}

func (g *Game) Draw(screen *ebiten.Image) {
    g.scene.Draw(screen)
}
```

切换场景：

```go
g.scene = NewPlayScene()
```

## 4.5 实体生命周期

子弹、粒子、敌人都需要创建和销毁。切片删除常见写法：

```go
alive := g.bullets[:0]
for _, b := range g.bullets {
    b.Update()
    if !b.Dead {
        alive = append(alive, b)
    }
}
g.bullets = alive
```

这个写法复用底层数组，减少分配。

## 4.6 简易粒子

```go
type Particle struct {
    X, Y float32
    VX, VY float32
    Life int
}

func (p *Particle) Update() {
    p.X += p.VX
    p.Y += p.VY
    p.VY += 0.08
    p.Life--
}
```

绘制时可以用 `vector.FillCircle`，高级一点再用小图片、颜色渐变或 blend。

## 4.7 官方 flappy 示例应学什么

`flappy` 不只是小游戏，它包含完整游戏循环的雏形：

- 玩家状态。
- 重力和跳跃。
- 障碍物生成。
- 碰撞检测。
- 分数。
- 游戏结束与重开。

建议把它作为第一个完整拆解案例。
