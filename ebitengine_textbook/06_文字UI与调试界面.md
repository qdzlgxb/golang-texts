# 06. 文字、UI 与调试界面

对应官方 examples：

```powershell

go run github.com/hajimehoshi/ebiten/v2/examples/texti18n@latest
go run github.com/hajimehoshi/ebiten/v2/examples/ui@latest

```

## 6.1 文本渲染

Ebitengine v2 时代常见选择有：

- `ebitenutil.DebugPrint`：调试最方便，但不适合正式 UI。
- `text/v2`：新版文本渲染，适合正式项目。
- bitmap font：像素风项目常用。

一个简单文本绘制例子：

```go
import (
    "github.com/hajimehoshi/bitmapfont/v4"
    "github.com/hajimehoshi/ebiten/v2/text/v2"
)

var face = text.NewGoXFace(bitmapfont.Face)

func drawText(screen *ebiten.Image, s string, x, y float64) {
    op := &text.DrawOptions{}
    op.GeoM.Translate(x, y)
    text.Draw(screen, s, face, op)
}
```

## 6.2 UI 的两种模式

### 即时模式 UI

每帧根据状态直接画按钮、检查鼠标是否点击。

优点：简单，适合游戏内菜单和调试工具。

缺点：复杂控件多了会难维护。

### 保留模式 UI

先创建按钮、布局、容器对象，然后由 UI 系统维护状态。

优点：适合复杂界面。

缺点：框架抽象更多。

Ebitengine 官方 examples 中有 `ui` 示例，`sprites` 和 `audio` 示例还使用了 `debugui` 展示调试面板。这类工具对开发期非常有用。

## 6.3 自己写一个按钮

```go
type Button struct {
    X, Y, W, H int
    Text       string
    Hovered    bool
}

func (b *Button) Update() bool {
    x, y := ebiten.CursorPosition()
    b.Hovered = x >= b.X && x < b.X+b.W && y >= b.Y && y < b.Y+b.H
    return b.Hovered && inpututil.IsMouseButtonJustPressed(ebiten.MouseButtonLeft)
}

func (b *Button) Draw(screen *ebiten.Image) {
    clr := color.RGBA{80, 90, 110, 255}
    if b.Hovered {
        clr = color.RGBA{110, 125, 150, 255}
    }
    vector.FillRect(screen, float32(b.X), float32(b.Y), float32(b.W), float32(b.H), clr, true)
    drawText(screen, b.Text, float64(b.X+8), float64(b.Y+8))
}
```

注意：按钮的 `Update` 返回“是否被点击”，由场景决定点击后做什么。

## 6.4 调试信息

建议每个项目早期都加一个调试开关：

```go
if inpututil.IsKeyJustPressed(ebiten.KeyF3) {
    g.debug = !g.debug
}
```

绘制：

```go
if g.debug {
    msg := fmt.Sprintf("TPS: %.2f\nFPS: %.2f\nObjects: %d", ebiten.ActualTPS(), ebiten.ActualFPS(), len(g.entities))
    ebitenutil.DebugPrint(screen, msg)
}
```

`ActualTPS` 比 `ActualFPS` 更适合衡量游戏逻辑是否稳定，因为游戏逻辑在 `Update` 中推进。

## 6.5 国际化文本

`texti18n` 示例值得关注：

- CJK 字体渲染。
- 双向文本。
- 字体 fallback。
- 复杂脚本文本布局。

如果你的游戏要支持中文、日文、韩文、阿拉伯文等，不要只用 bitmap font 糊弄过去。正式项目应把字体、语言、排版当成独立模块。

## 6.6 UI 状态管理建议

小项目可以把 UI 放在 Scene 里：

```go
type MenuScene struct {
    start Button
    quit  Button
}
```

中型项目建议拆出：

```text
internal/ui/
  button.go
  label.go
  panel.go
  layout.go
```

不要一上来写通用 UI 框架。先服务当前游戏。
