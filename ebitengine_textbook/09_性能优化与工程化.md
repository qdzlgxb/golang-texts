## 9.1 性能优化先看 draw command

Ebitengine 的一个关键性能原则是：**相似绘制调用连续出现，内部更容易合批。**

尽量：

- 相同 target 连续画。
- 相同 blend 连续画。
- 相同 filter 连续画。
- 使用图集减少纹理切换。
- 不在绘制过程中频繁切换 shader/offscreen。

运行调试标签查看内部绘制情况：

```powershell
go run -tags=ebitenginedebug github.com/hajimehoshi/ebiten/v2/examples/blocks@latest
```

## 9.2 避免每帧分配

坏例子：

```go
func (g *Game) Draw(screen *ebiten.Image) {
    img := ebiten.NewImage(16, 16) // 不要每帧创建
    screen.DrawImage(img, nil)
}
```

好例子：

```go
type Game struct {
    bulletImage *ebiten.Image
}
```

资源在初始化时创建，游戏循环中复用。

```go
g.tmpIDs = ebiten.AppendGamepadIDs(g.tmpIDs[:0])
```

```go
alive := g.particles[:0]
for _, p := range g.particles {
    p.Update()
    if p.Life > 0 {
        alive = append(alive, p)

```

## 9.4 逻辑与绘制分离

不要在 `Draw` 中做：

- 角色移动。
- 碰撞检测。
- 创建敌人。
- 随机掉落。
- 文件 IO。
- 网络请求。

`Draw` 应该尽量是纯表现层。

## 9.5 资源管理

推荐使用 `go:embed`：

```go
package assets

import "embed"

//go:embed images/*.png audio/*.wav
var FS embed.FS
```

加载图片：

```go
func LoadImage(name string) (*ebiten.Image, error) {
    b, err := assets.FS.ReadFile(name)
    if err != nil {
        return nil, err
    }
    img, _, err := image.Decode(bytes.NewReader(b))
    if err != nil {
        return nil, err
    }
    return ebiten.NewImageFromImage(img), nil
}
```

## 9.6 游戏工程结构

中小型项目建议：

```text
mygame/
  cmd/mygame/main.go
  internal/game/game.go
  internal/game/scene.go
  internal/game/input.go
  internal/game/audio.go
  internal/game/assets.go
  internal/game/world.go
  internal/game/entity.go
  assets/images/
  assets/audio/
```

对于 Ebitengine，不必急着做“通用游戏框架”。先做游戏，再抽象公共能力。

## 9.7 时间步长

Ebitengine 的 `Update` 默认按固定 tick 调用。大多数 2D 游戏可以直接每 tick 推进固定量：

```go
player.X += player.VX
```

不要一开始就引入 delta time。固定 tick 更容易处理碰撞、回放、确定性逻辑。

需要变速、暂停、慢动作时，可以自己在 `Update` 中管理逻辑 tick。
