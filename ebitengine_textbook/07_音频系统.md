# 07. 音频系统

对应官方 examples：

```powershell
go run github.com/hajimehoshi/ebiten/v2/examples/audio@latest
go run github.com/hajimehoshi/ebiten/v2/examples/sinewave@latest
go run github.com/hajimehoshi/ebiten/v2/examples/wav@latest
go run github.com/hajimehoshi/ebiten/v2/examples/piano@latest
```

## 7.1 音频的基本概念

Ebitengine 的音频系统围绕几个概念：

- `audio.Context`：音频上下文，通常整个游戏一个。
- `audio.Player`：播放一个音频流或音频数据。
- decoder：把 MP3、Ogg/Vorbis、WAV 等格式解码成音频流。
- sample rate：采样率，常见 44100 或 48000。

## 7.2 初始化音频上下文

```go
const sampleRate = 48000

type Game struct {
    audioContext *audio.Context
}

func NewGame() *Game {
    return &Game{
        audioContext: audio.NewContext(sampleRate),
    }
}
```

## 7.3 音效与音乐分开处理

建议分成两类：

- **BGM**：长音频，循环播放，通常同时只有 1 首。
- **SE/SFX**：短音效，可能频繁重复播放，比如跳跃、攻击、点击。

伪结构：

```go
type AudioManager struct {
    ctx    *audio.Context
    bgm    *audio.Player
    sounds map[string][]byte
}
```

短音效可以预先读入内存，播放时创建 player：

```go
func (a *AudioManager) PlaySound(name string) {
    b := a.sounds[name]
    p := a.ctx.NewPlayerFromBytes(b)
    p.Play()
}
```

实际项目还要管理 player 生命周期，避免大量已结束 player 堆积。

## 7.4 音量曲线

不要简单认为滑条 0.5 就是“听起来一半音量”。人的听觉更接近对数感知。官方 `audio` 示例里展示了不同音量曲线的处理思路。你可以设计：

```go
func volumeFromSlider(v float64) float64 {
    // v: 0..1
    return v * v
}
```

这会让低音量区间更细腻。

## 7.5 Web 平台音频限制

浏览器通常要求用户交互后才能启动音频。发布 Web 版本时，要把“开始游戏”按钮作为音频解锁点，避免一进页面就播放。

## 7.6 音频管理建议

简单项目：

```text
assets/audio/
  jump.wav
  hit.wav
  bgm.ogg
```

中型项目：

```go
type SoundID string

const (
    SoundJump SoundID = "jump"
    SoundHit  SoundID = "hit"
)
```

不要在游戏逻辑里写文件名。游戏逻辑只说“播放 Jump 音效”，音频系统负责找到资源。

## 7.7 官方 audio 示例应学什么

`audio` 示例值得拆解：

- 多种格式解码。
- 播放/暂停。
- seek 进度条。
- 音量模式。
- 背景状态下的行为。
- 鼠标/触摸控制播放按钮。

它是音频系统的综合案例。
